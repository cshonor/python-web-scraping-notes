# 第 18 章 网页抓取的法律与道德约束：学习笔记

前面十七章回答的都是「**能不能**抓」——怎么解析 HTML、怎么对付 JavaScript、怎么并发。本章回答的是另外两个更根本的问题：「**该不该**抓」和「**以什么方式**抓」。写爬虫的人常把自己定位为纯工程师，但爬虫直接作用于他人的服务器、数据库与商业模式：一旦越界，等待你的往往不是一封 403，而是律师函、禁令乃至刑事指控。本章的核心立场一句话：**技术可行 ≠ 法律允许，更 ≠ 道德上站得住脚**；而且「降低对他人系统的伤害」与「降低自身法律风险」在工程上是同一套动作，不是两笔预算。所以这一章请带着「将来某个决定可能要向律师、法官或媒体解释」的心态来读，而不是当成可以跳过的免责声明。需要再次强调：本章是**通识教育向的学习笔记**，不构成任何法域的法律意见。

**本章目标**

1. 理清美国语境下与抓取最相关的几条法律线索（CFAA、版权、侵犯动产、商业秘密、DMCA、合同）各自**管什么**
2. 能从几个经典判例中提炼出「**法院真正在乎什么**」的判断维度，而不是背案名
3. 能把抽象的道德判断落地为**可执行的工程 checklist**（限速、标识、数据分级、留证、熔断）
4. 养成「动手写第一行 `requests.get` 之前先做合规自检」的习惯
5. 明确本章内容的边界：学习笔记不能替代**执业律师的意见书**与正式合规评估

## 1. 核心法律框架（以美国判例与立法为线索）

之所以以美国为线索，是因为原书面向英文读者，且迄今绝大多数有影响力的爬虫诉讼发生在美国法院。但这**不代表**其他法域可以忽略：欧盟 GDPR 对个人数据的处理（包括「自动化收集」这一动作本身）有独立约束；中国的《著作权法》《数据安全法》《个人信息保护法》以及反不正当竞争相关司法解释，同样可能覆盖抓取行为。**跨境抓取必须逐法域分别评估**，不能用「在美国可能没事」推导「在全球都没事」。

读这一节时请记住一个方法论：现实中的诉讼几乎从不单挑一条法律，而是**组合拳**——同一份起诉书里同时出现 CFAA、版权、违约、不正当竞争是常态。因此下面的分类是为了学习方便，风险判断时必须把各条线**叠加**起来看，而不是找到一条「打不中我」就高枕无忧。

### 1.1 《计算机欺诈与滥用法》（CFAA）

- **它管什么**：CFAA 是一部 1980 年代制定的反黑客法律，核心是禁止「未经授权」或「超出授权范围」访问受保护的计算机并造成特定后果。它有民事与刑事两个侧面，因此风险等级远高于一般的合同纠纷。
- **关键争议点**：「授权」二字从未被精确定义。一个无需登录就能打开的公开网页算不算「被授权访问」？被网站明确发函要求停止之后继续抓，是否就从「授权」变成「未授权」？这些问题在司法史上摇摆了二十多年。2021 年前后，美国最高法院在一起与爬虫无直接关系、但解释同一法条的案件中**收窄**了「超出授权访问」的口径（该案的通俗概括是：滥用「本就有权访问」的数据，不等于「越权访问」），此后下级法院对「纯公开页面」的 CFAA 指控趋于谨慎——但「趋于谨慎」不等于「豁免」。
- **对爬虫意味着什么**：风险随行为性质陡增。**只读公开页面**处在争议区的浅色端；而**使用他人账号、绕过登录墙、伪造会话、被明确封禁后换 IP 继续**则迅速滑向深色端。一个实用的内部规则：凡是需要「骗过对方认证体系」才能拿到的数据，先停下来走法务流程。
- **刑事与民事的双轨**：CFAA 既有刑事追诉条款，也允许受害方提起民事诉讼。这意味着风险不只来自「会不会有检察官感兴趣」，还来自「对方公司愿不愿意花钱告你」——后者的门槛要低得多。

### 1.2 版权法（Copyright）

- **它管什么**：保护具有独创性的**表达**——文章的文字组织、摄影、美术作品、版面设计等。**事实本身**（某公司股价、某场比赛比分、某人的姓名出现在某个名单上）通常不受版权保护，这是抓取从业者最常援引的安全岛。
- **对爬虫意味着什么**：
  - 「事实不受保护」**不等于**「事实的集合可以随便搬」。对事实的**选择与编排**若体现独创性，可能构成受保护的汇编作品。
  - 抓取、存储、再发布是三个风险递增的动作。为分析而**临时落盘**与把内容**原样搬到自己网站上**是两回事，后者几乎必然触发版权问题。
  - **数据库与规模**是另一个放大器：即便单条数据无版权问题，成规模、成体系地搬走对方的整个数据库，仍可能触发数据库特别权利（部分法域）、合同或不正当竞争主张——「每条都合法」推不出「整体合法」。
  - 美国法下的**合理使用**（fair use）是一个四要素的综合测试（使用目的与性质、作品性质、使用比例、对市场的影响）。「非商业使用」只是其中一个有利因素，**不能**简化为「不赚钱就安全」；「转换性使用」（搜索引擎建索引、训练分析模型做统计）与「替代性使用」（原文照登抢流量）的后果完全不同。

### 1.3 侵犯动产（Trespass to Chattels）

- **它管什么**：一个古老的普通法侵权概念，原指未经许可**干扰他人有形动产**并造成损害。数字时代，部分法院将其类比到「未经许可占用他人计算机系统资源」上。
- **对爬虫意味着什么**：它给了网站一个在版权和 CFAA 之外的抓手——即使抓的内容没有版权、页面完全公开，只要你的请求**实际消耗或贬损了对方系统资源**（挤占带宽、拖慢真实用户、迫使对方扩容），就可能构成损害。反过来说，这个理论通常要求**可证明的损害**，礼貌、低量、未造成功能影响的抓取很难被它单独打中。它惩罚的是「鲁莽与贪婪」，不是「自动化」本身。
- **常见讨论点**：超高频请求导致服务降级、无视对方配额体系、在对方明确限流后绕过限制继续加压——这些场景下动产侵害常与违约主张**打包出现**（视事实与法域而定）。但必须强调：**不等于**所有抓取都构成该侵权，「造成损害」是构成要件而非默认前提。

### 1.4 商业秘密（Trade Secret）

- **它管什么**：因**不为公众所知**而具有经济价值、且权利人已采取**合理保密措施**的信息。客户名单、未公开的定价模型、内部评分规则都可能落入。
- **对爬虫意味着什么**：登录墙、NDA、内部权限本身就是「合理保密措施」的证据。绕过这些措施拿到的数据，几乎天然带着商业秘密诉讼的引信。还有一种更隐蔽的风险：单项公开、但**聚合后**能反推出商业秘密（如用公开招聘信息反推某公司未发布的产品线）——这种「马赛克效应」在争议中常被主张，值得在数据分级时纳入考量。
- **与 CFAA 的分工**：CFAA 关心「你怎么进来的」，商业秘密关心「你拿走的是什么」。一次越权访问若拿走的恰好是保密信息，两条线会同时点燃，这也是「登录墙后的数据」风险等级远高于公开页面的原因。

### 1.5 DMCA（数字千年版权法）与反规避

- **它管什么**：两部分与爬虫相关——其一，禁止**规避技术保护措施**（加密、DRM、访问控制机制）；其二，为网络服务商提供**安全港**。
- **对爬虫意味着什么**：反规避条款的严厉之处在于它**可以独立于版权侵权成立**——即使你绕开技术措施后拿的内容本身不构成侵权，「绕」这个动作本身就违法。因此遇到付费墙、加密接口、设备指纹验证时，「技术上能绕」恰恰是**最不该绕**的信号。
- **安全港的另一面**：DMCA 的安全港制度主要保护平台方（搜索引擎、托管商），Field v. Google 案中它发挥了重要作用；但对「主动抓取并自行发布」的一方，安全港基本帮不上忙——别把它当成爬虫的护身符。

### 1.6 合同：服务条款（ToS）与 `robots.txt`

- **它管什么**：合同法的领地。网站的服务条款能否约束你，取决于法院是否认定你与网站之间**成立了合同**——注册账号时点过「同意」（clickwrap）的约束力远强于页脚一个链接（browsewrap）。
- **对爬虫意味着什么**：
  - ToS 中明确禁止自动化抓取的条款**可能**具有合同效力，判断以条款文本、成立方式与所在法域为准。
  - `robots.txt` 本身不是法律，是行业惯例性的**爬取礼貌声明**。但在诉讼中它常被用作「你已被告知边界却执意越过」的**主观恶意旁证**；若你与站点另有合同关系，违反它还可能构成违约。
  - 收到对方的停止函（cease-and-desist）之后继续抓，会把所有模糊地带全部点亮成红灯——此时「不知者不怪」的辩护空间基本消失。
- **工程上的可执行规则**：把「读过目标站 ToS 与 robots 并留档」列为抓取项目的第一条验收标准；团队里至少要有人能回答「我们与这个站点之间有没有合同关系」——注册过账号、点过同意框、用过其 API，答案就可能是「有」。

### 1.7 各线索速查表

| 法律线索 | 它管什么 | 对爬虫意味着什么 | 典型风险触发点 |
|---|---|---|---|
| **CFAA** | 未经授权/超授权访问计算机 | 「授权」边界随判例摇摆，近年对纯公开页面趋于谨慎 | 用他人账号、绕登录、被封后换 IP 继续 |
| **版权法** | 独创性表达，不含事实本身 | 事实可抓，编排与再发布另算；合理使用是综合测试 | 原文照登、大规模镜像、替代性使用 |
| **侵犯动产** | 干扰他人动产造成损害 | 惩罚「占用对方系统资源」的行为 | 高频请求致服务降级、无视配额 |
| **商业秘密** | 保密措施下的非公开信息 | 登录墙/NDA 是保密措施的证据 | 绕过访问控制；聚合反推（马赛克效应） |
| **DMCA** | 反规避技术措施 + 安全港 | 「绕」本身可独立违法，与是否侵权无关 | 破 DRM、绕付费墙、绕设备指纹 |
| **合同/ToS** | 用户与网站间的约定 | 视合同成立方式而定；停止函后风险陡增 | 注册账号后违反条款、收到函件不停手 |
| **robots.txt** | 行业惯例，非法律 | 礼貌声明 + 恶意旁证 | 明令 Disallow 仍抓取 |
| **GDPR（欧盟）** | 个人数据的自动化处理 | 抓取动作本身即可能构成「处理」，需合法性基础 | 批量收集欧盟数据主体的公开资料并画像 |
| **中国法域** | 著作权、数据安全、个人信息保护 | 数据出境、敏感个人信息均有独立红线 | 抓国内平台用户数据后跨境传输 |

## 2. 经典案例（高度摘要，非判词复述）

以下均为**公开常识层面的概括**，刻意模糊具体案号与判决日期；要引用请查原始卷宗。每个案例按「双方 — 争点 — 结果 — 启示」组织，重在提炼法院的判断维度，而非复述判词。

读判例时警惕两种误用：一是把**对自己有利的那一个**当成普遍规则（hiQ 案常被这样引用）；二是把**早期、管辖有限**的判决当成终审真理。判例法是一层层覆盖修正的沉积岩，本节给的只是每个案子「被记住的理由」，不是现行有效的完整法律状态。

### 2.1 eBay 诉 Bidder's Edge

- **双方**：拍卖巨头 eBay，对一家聚合多个拍卖站报价的比价服务。
- **争点**：对方的爬虫每日发起大量自动请求，虽只占 eBay 总负载的一小部分，eBay 主张这种**持续、未经许可的资源占用**构成对其系统的侵害。
- **结果**：法院在大约世纪之交发布了**初步禁令**，要求停止抓取，动产侵害理论在其中发挥了重要作用。
- **启示**：「我只占你 1% 的带宽」不是有效的抗辩——**未经许可 + 持续占用 + 对方明确反对**，三者齐备时，比例再小也可能被禁。该案也确立了「服务器是别人的财产」这一朴素直觉在诉讼中的分量。它至今仍是被引用最多的「爬虫第一案」，动产侵害这条看似古老的理论因此一直是网站方武器库里的常备选项。

### 2.2 Field 诉 Google（搜索引擎缓存案）

- **双方**：一位把作品放上个人网站的作者，对 Google 的网页缓存功能。
- **争点**：搜索引擎抓取并缓存网页全文，是否侵犯版权。
- **结果**：法院在 2000 年代中期支持了 Google，理由包括行业通行的 **opt-out 机制**（meta 标签、robots.txt）未被使用、缓存的转换性、以及 DMCA 安全港等因素。
- **启示**：当站点存在**标准化的拒绝表达渠道**而权利人不用时，法院倾向于让沉默者承担部分后果。但别过度外推——这个结论保护的是「**带退出机制的索引与缓存**」，不是「对普通站点做全文镜像并对外提供」。Google 有品牌、有合规团队、还能给被收录方带去流量；普通抓取者三样都没有，判决里的有利因素不会自动平移到你身上。

### 2.3 美国诉 Auernheimer（「weev」案）

- **双方**：美国联邦政府，对一名通过枚举公开 URL 批量获取用户邮箱地址的安全研究员。
- **争点**：AT&T 的一个接口对任何构造好 URL 的访问者直接返回 iPad 用户邮箱，无需密码。**「公开可访问」是否等于「获得授权」**，成为 CFAA 适用的核心争点。
- **结果**：一审定罪，上诉阶段在 2010 年代中期因**管辖地问题**被撤销，法院刻意避开了对实体问题的最终裁断，留下一片争议。
- **启示**：「地址栏里能打开」不等于「法律上欢迎你批量来拿」。通过**枚举、猜测标识符**绕过设计意图获取数据，即使没有任何密码被破解，也足以让你站上被告席。此案同时展示了 CFAA 刑事一侧的威慑力。值得玩味的是，它最终以程序理由而非实体理由收场——「公开可访问资源上的 CFAA 边界」这个核心问题被留给了后来的判例，这也是 hiQ 案会被如此关注的原因之一。

### 2.4 Craigslist 诉 3Taps

- **双方**：分类广告站 Craigslist，对一家把其广告数据聚合后通过 API 转售的初创公司 3Taps。
- **争点**：广告内容本身多为事实性信息、版权归属存疑，但 Craigslist 已发出停止函并实施 IP 封锁，3Taps 改用轮换 IP 继续抓取——**「被明确告知停止后继续」是否使访问变为「未经授权」**。
- **结果**：2010 年代初的诉讼进程中，法院认可了这一阶段 CFAA 主张可以继续推进，「停止函 + 技术封锁」被看作撤销授权的有效信号；案件后来以和解与高额赔偿安排的报道收尾。
- **启示**：本案与 hiQ 案看似结论相反，拼起来才是完整图景——**法院真正看重的分水岭不是「页面公不公开」，而是「对方有没有明确说不、你听没听」**。收到停止函之后每多抓一页，都是在给对方递证据。

### 2.5 hiQ 诉 LinkedIn

- **双方**：一家做职场数据分析的小公司 hiQ，对微软旗下的 LinkedIn。hiQ 的商业模式依赖抓取用户**公开**的职业档案。
- **争点**：LinkedIn 发函禁止并实施技术封锁后，hiQ 继续抓取公开页面，是否违反 CFAA。hiQ 罕见地以原告身份主动出击，请求法院确认其行为合法。
- **结果**：拉锯数年。上诉法院在 2010 年代末至 2020 年代初的倾向性意见对 hiQ 有利：**抓取公开数据大概率不构成 CFAA 下的「未经授权访问」**，最高法院收窄解释「超授权访问」后这一立场得到强化。但 CFAA 只是多份诉状中的一个案由，合同、不正当竞争等其他主张并未被一并清除；双方最终在 2020 年代初以和解/撤诉收场，hiQ 本身也没能活成一家持续经营的公司。
- **启示**：这是爬虫从业者引用最多的案例，也最容易被**断章取义**——它说的是「公开数据 + CFAA 大概打不中你」，而不是「公开数据随便抓」。合同主张、州法主张、以及「耗也能把你耗死」的诉讼成本，一样不少。
- **对策略的现实影响**：即便你确信自己在 CFAA 一侧站得住，也要想清楚——对方有十倍于你的律师预算时，「最终能赢」与「撑到最终」是两回事。hiQ 案的持久价值不在胜负，而在于它演示了**一场爬虫诉讼可以同时动用多少条法律线索**，以及小公司在这场消耗战里的真实处境。

### 2.6 案例启示速查表

| 案例 | 法院在乎的核心问题 | 对从业者的启示 |
|---|---|---|
| eBay v. Bidder's Edge | 是否未经许可持续占用对方资源 | 占比小不是抗辩；明确反对后必须停 |
| Field v. Google | 权利人是否使用了标准 opt-out 机制 | 尊重 robots/meta；但结论不可外推到镜像 |
| 美国诉 Auernheimer | 「公开可访问」是否等于「授权」 | 枚举绕过设计意图 ≈ 制造证据指控自己 |
| Craigslist v. 3Taps | 停止函 + 技术封锁是否撤销了授权 | 收到函件后绕道继续 = 风险陡增的起点 |
| hiQ v. LinkedIn | 公开数据的 CFAA 边界 | CFAA 风险下降 ≠ 全面豁免；诉讼成本本身是惩罚 |

把这五行放在一起，可以提炼出一张**简化的风险判断轴**：数据越公开、行为越克制、对方越沉默，风险越低；数据越封闭、行为越具对抗性（绕封锁、骗认证）、对方越明确反对，风险越高。判例之间的「矛盾」大多可以在这条轴上得到解释——它们量的从来不是同一个点。

## 3. 抓取道德与工程准则（重要）

道德不是法律胜诉后的装饰品，而是**低成本的前置风控**。以下把抽象准则翻译成可以直接写进工程规范的动作。

一个总的判断：**法庭上的「恶意」往往由工程细节拼出来**——你的 User-Agent 写了什么、被封后换没换 IP、日志里有没有「他们开始封了，加点代理」这样的提交记录。道德准则与工程准则是同一份证据的一体两面。

### 3.1 把「不伤害」写成参数，而不是口号

| 道德直觉 | 工程落地 |
|---|---|
| 别挤占对方资源 | `DOWNLOAD_DELAY`、单域名并发上限、尊重 `429` 与 `Retry-After`、指数退避 |
| 别在业务高峰添乱 | 任务排程避开对方时区的白天与促销节点 |
| 让对方找得到你 | `User-Agent` 写明 bot 名、版本、**真实联系邮箱**，并附说明页 |
| 尊重对方的拒绝表达 | 默认遵守 `robots.txt`；遇到 ToS 明令禁止时停下而不是绕过 |
| 不给对方留安全隐患 | 不提交探测性 Payload、不碰登录/找回密码等敏感端点 |

### 3.2 数据分级先行

在写爬虫之前先给目标数据分级，不同级别走不同审批：

| 级别 | 例子 | 动作 |
|---|---|---|
| **公开无敏感** | 商品公开价格、公开文档 | 正常礼貌抓取 |
| **需谨慎** | 用户公开资料、评论（可能含个人信息） | 最小化字段、脱敏存储、限定用途 |
| **敏感** | 个人可识别信息、账号体系内数据 | **先过法务/隐私评审**，否则不碰 |
| **禁止** | 商业秘密、绕技术措施才能获得的数据 | 不做，换官方渠道或放弃 |

两个容易忽视的落地细节：

- **分级要打标签**：分级结论应写进数据 schema 或入库元数据（如 `sensitivity=internal`），让下游每个消费者都知道自己手里是什么；只存在于 Wiki 页面里的分级等于没有分级。
- **降级要有出口**：评审认为级别定高了、数据其实可以公开抓，应走正式降级流程并留痕，而不是工程师私下「通融」——否则下次定级就没有人当真了。

### 3.3 沟通优先于对抗

很多机构愿意在**受控 API、白名单、数据共享协议**下提供数据——一封说明来意的邮件，成本远低于一次应诉。把「发邮件要授权」列为正式方案而非示弱：拿到书面许可后，限速、字段、保留期限都可以写进协议，后续反而是**最省心**的抓取方式。

反过来说，**对抗性技术手段本身就是证据**：轮换 IP 池、伪造浏览器指纹、破解验证码，这些动作在工程上是「能力」，在法庭上读出来全是「明知对方拒绝仍执意为之」。一个越费尽心机绕开封锁的系统，越是把「善意」这条退路亲手堵死。

### 3.4 可问责：出事之前先排练

- **日志留证**：记录抓取范围、频率、时间与遵守 robots 的证据——真被质疑时，这是证明「善意且克制」的唯一材料。注意日志本身也要分级保存：抓了什么字段可以记，抓到的敏感内容**正文**不要再复制一份进日志。
- **熔断开关**：一个能在几分钟内停掉全部抓取任务的开关，写进运维手册。定期演练一次——没演练过的开关等于没有。
- **善后流程**：收到函件后的联系人、停抓 SOP、数据删除与更正机制，事前约定，事中不慌。其中「数据删除」要覆盖到备份与下游副本，只删主库在法律上很难自圆其说。

### 3.5 灰色地带的判断顺序

遇到「好像可以、又好像不行」的场景，按这个顺序问自己，任何一步答「否」就停下：

1. **换我是对方站长，我会觉得被冒犯还是被服务？**（道德直觉先行，它往往比法律分析更快命中要害）
2. **对方有没有说过「不」？**（robots、ToS、停止函，强度递增）
3. **我拿到数据后要拿它做什么？**（分析留证 vs 原样再发布，风险天差地别）
4. **如果明天这件事登上行业媒体头条，我能否坦然解释每一个技术决策？**（「报纸头条测试」比多数内部合规培训更有效）
5. **这个决定我敢不敢写给律师看？**（不敢写的部分，就是不该做的部分）

本章全部内容为**学习笔记性质的通识整理**，作者与整理者均不以律师身份提供意见；法律条文与判例的表述只到「公开常识可验证」的粒度，具体案件结果高度依赖事实细节与管辖法域，且判例法持续演变，文中任何「趋于」「大概」之类的措辞都可能在明天被新判决改写。**涉诉风险评估、商业产品合规审计、跨境数据方案，请务必咨询有执业资格的律师**，并以正式法律意见书为准。与第 3、14、16 章反复强调的一致：**降低伤害 = 降低自身风险**，这是工程结论，不是法律结论。

## 5. 项目启动前的自检清单（替代「技巧万能论」）

「这个网站技术上能不能抓」永远是错误的第一问。正确顺序是先过下面这份清单——任何一栏答不上来，就先补作业再写代码：

| 分组 | 自检问题 | 勾选 |
|---|---|---|
| 业务 | 我到底要解决什么业务问题？需要哪些**字段**、多少**量**、什么**频率**？ | ☐ |
| 业务 | 是否已有**官方 API / 付费数据 / 授权渠道**可以拿到同样数据？ | ☐ |
| 法律 | 目标站的 **ToS 与 robots.txt** 是否禁止我的行为？我是否与站点存在账号合同关系？ | ☐ |
| 法律 | 数据属于哪一级（第 3.2 节分级表）？涉及个人信息或商业秘密时，**法务是否已评审**？ | ☐ |
| 法律 | 抓取后会不会**再发布**？发布形态是转换性使用还是替代性使用？ | ☐ |
| 法律 | 数据是否跨境流动？涉及欧盟数据主体时 **GDPR**、涉及中国境内数据时**国内三法**是否已评估？ | ☐ |
| 技术 | 定位方案是否**稳定可维护**？页面改版时如何**优雅降级**而不是静默出错？ | ☐ |
| 技术 | 频率、并发、退避是否设了**硬上限**？被封禁后是停止还是绕道（后者需重新过法律栏）？ | ☐ |
| 技术 | 是否需要**绕过**任何认证、加密或反爬措施才能拿到数据？（「是」≈ 停止信号） | ☐ |
| 运维 | 日志是否足以**自证克制**？熔断开关与数据删除流程是否就绪？ | ☐ |
| 运维 | 数据的**保留期限**与到期删除机制是否明确？ | ☐ |
| 运维 | 收到停止函后的**联系人与响应时限**是否写进了值班手册？ | ☐ |

**比喻**：互联网可以看作一个「**UI 不统一、文档不完整的大型系统**」——工程上我们几乎总能找到自动化的办法拿到信息（`requests`、官方 API、浏览器自动化、OCR、分布式队列只是工具箱里的不同扳手），但**选择哪把扳手，必须在法律与合同框架内决定**。技巧解决的是效率，清单解决的是资格。

这份清单的正确用法不是「抓之前填一次就完事」，而是**随项目生命周期反复回填**：需求变更加了新字段 → 重过法律栏；目标站改版 → 重过技术栏；收到一封措辞强硬的邮件 → 直接触发熔断流程而不是重填清单。清单的价值在于把「合规」从一次性审批变成持续状态。

## 练习建议

1. 挑两个你常用的网站，完整读一遍 **ToS + robots.txt**，各写 5 条「允许 / 禁止」摘要，并标注依据来自条款原文还是你的推断。
2. 为你的团队起草一页**「抓取数据分级」**制度（公开 / 需谨慎 / 敏感 / 禁止），每级给出两个真实业务例子与对应审批人。
3. 把第 5 节自检清单改造成你们仓库的 **PR 模板**，并为一个历史项目补填一次，看看哪些格子当时根本没人问过。
4. 以公开报道为素材，给 hiQ v. LinkedIn 做一页时间线，重点回答：「赢了 CFAA 论点的一方，为什么商业模式仍然没活下来？」再对照 Craigslist v. 3Taps，总结「收到停止函」在两条故事线里分别扮演了什么角色。
5. 假设你负责的项目明天收到一封停止函，写出**应急 SOP**：谁看邮件、谁按熔断、数据删多少、回函由谁起草——写不出来的环节就是现在该补的。
6. 找一个提供**官方 API** 的站点，对比「API 方案」与「直接抓 HTML 方案」在字段覆盖、速率限制、法律确定性上的差异，写一页选型建议。
