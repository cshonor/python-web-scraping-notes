# 第 3 章 编写网络爬虫：学习笔记

第 1、2 章都是「单页」：给一个 URL，取一次，解析一次。本章把爬虫推成**会走路的**东西 —— 从一页拿到链接，筛选、去重、跳进去，再拿链接。一旦开始「自动跳转」，两个新问题立刻出现：**怎么不让它绕圈子**，以及**怎么不让对面把你封了**。

**本章目标**

1. 编写能在站内**自动跳转**的爬虫（遍历）
2. **链接去重**，避免重复与死循环
3. **筛选有效链接**，减少菜单、页脚等噪声
4. 写出带异常处理、**可安全停止**的循环/递归思路
5. **礼貌抓取**：延迟、限速、遵守 `robots.txt`

---

## 1. 核心知识点与原理

### 1.1 爬虫本质：从一页到另一页

1. 打开页面
2. 提取链接
3. **过滤**出目标链接
4. **去重**（`set`）
5. 继续请求 → 循环或队列扩展

第 3、4 步是本章的全部价值所在；第 1、2、5 步第 1 章已经会了。

### 1.2 链接过滤（维基词条示例）

以维基百科为例，有效的词条链接要同时满足：

- 路径以 **`/wiki/`** 开头
- **不含冒号**（排除 `Special:`、`Help:`、`File:` 等名字空间）
- 尽量只在 **`#bodyContent`** 内取 `<a>`，减少侧栏、导航模板噪声

```python
re.compile(r"^(/wiki/)((?!:).)*$")
```

### 1.3 去重

**`set()`** 是标准做法：插入与成员测试平均 O(1)，用它记录已访问过的路径即可。换成 `list` 并在里面 `in` 查，规模上去后会是 O(n²) 的灾难。

### 1.4 递归 vs 队列

| 方式 | 优点 | 代价 |
|---|---|---|
| **递归** | 代码短，贴合「深度优先」直觉 | 受递归深度与栈限制，几千层就爆 |
| **显式队列/栈（BFS/DFS）** | 可断点续爬、可限流、可分布式 | 代码稍长 |

生产环境基本都走后者 —— 第 16 章的多线程抓取也是在这个结构上加并发。

### 1.5 爬虫礼仪

- **`time.sleep`** 限速，控制总请求量
- **异常处理**：单页失败不能拖垮整批任务
- **`robots.txt` 与站点条款**：详见第 18 章；维基有明确的机器人政策，且**要求可识别的 User-Agent 带联系方式**

## 2. 异常处理与最佳实践（易错点）

1. **不去重** → 来回跳转、资源耗尽（A→B→A 死循环是最常见的翻车方式）
2. **不过滤** → 爬进非目标名字空间或噪声链接，几分钟就把队列撑到几万条
3. **无延迟** → 触发 429 / 封 IP
4. **无异常处理** → 一个 404 让整批任务中断
5. **相对/绝对 URL 混用** → 去重失效或请求 404，用 **`urllib.parse.urljoin`** 统一成绝对地址再入队

第 5 条最阴：`/wiki/Python` 和 `https://en.wikipedia.org/wiki/Python` 在 `set` 里是**两个不同的字符串**，不去规范化就等于没去重。

## 3. 示例代码

主示例：**`chapter-03/wikipedia_crawler.py`**

实现要点：**`Request` + 合规 User-Agent**、**`#bodyContent` + 正则**双重过滤、**`set` 去重**、**`time.sleep`** 限速、**最大页数上限**保证能停、**`href` 判空**。


**运行前必做**：把脚本里 `User-Agent` 的 **`mailto:you@example.com`** 换成你的真实联系方式（见[维基 User-Agent 政策](https://meta.wikimedia.org/wiki/User-Agent_policy)）。不改的话容易被直接 403。

---

## 4. 学习贴士

- **给爬虫设「刹车」比设「油门」重要**。`MAX_PAGES` 之类的上限不是偷懒，是让你按 Ctrl-C 之前它已经自己停下了。
- **限速要算绝对数值**。`sleep(1)` 意味着单线程最多 1 QPS，10 万页就是 28 小时 —— 先算清楚再跑。
- **维基、GitHub 这类站点对 UA 敏感**，把联系方式写进去是「不被封」的最低成本手段。
