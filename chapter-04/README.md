# 第 4 章 网络爬虫模型：学习笔记

第 3 章的爬虫只能爬维基 —— 把站点名、`/wiki/` 前缀、`#bodyContent` 全写死在代码里了。多来两个站，就变成三个互相分叉的脚本，改一处忘两处。本章做的是**把「去哪取」和「怎么取」拆开**：解析规则变成配置，引擎只写一遍，新增站点只是多加一个配置对象。

**本章目标**

1. 编写**可复用、可扩展、跨网站**的通用爬虫思路
2. 理解 **数据模型 + 配置分离**：解析规则不进业务硬编码
3. 使用 **`Website` + `Crawler` + `Content`** 三层分工
4. **一套解析流程**适配多站：改配置为主、改引擎为辅
5. 避免「一站一脚本」导致的重复与分叉维护

---

## 1. 核心知识点与原理

### 1.1 什么是「爬虫模型」

把爬虫拆成三块：

| 部分 | 职责 |
|---|---|
| **`Content`（数据模型）** | 统一存放结果：URL、标题、正文等 |
| **`Website`（配置模型）** | 每站的 **CSS 选择器**、名称、根 URL 等「抓取指令」 |
| **`Crawler`（引擎）** | 请求、按 `Website` 抽取、组装为 `Content` |

### 1.2 三大核心类

1. **`Content`**
   各站最终都落到**同一字段集合**，便于入库、对比、分析。这是三层里最不该变的一层 —— 下游的存储、统计、管道全靠它稳定。
2. **`Website`**
   只描述「**去哪取**」：标题在 `h1`、正文在 `div.content p`。改版时优先改**配置**，而不是复制整段爬虫逻辑。
3. **`Crawler`**
   统一 `get_page` → `safe_get` → `parse`。可选 **`parse_from_soup`**：对已拿到的 `BeautifulSoup` 做纯解析，用于离线 fixture 与单元测试。

### 1.3 安全提取：`safe_get`

- `soup` 为 `None` 或选择器无匹配时返回 **`""`**，不抛异常
- 多节点时用 **`"\n".join(...)`** 合并段落
- 与第 2 章「先判断再 `.`」一脉相承，是稳健爬虫的标配

### 1.4 CSS 选择器

- `soup.select("h1")`、`".class"`、`"#id"`、后代组合等
- 相对 `find` / `find_all`，选择器**表达力更强、配置更短**，而且天然是**一个字符串** —— 这就是它能被塞进 `Website` 配置的前提

### 1.5 请求与限速

- 用 **`requests.Session()`** 复用连接、统一 **User-Agent**
- **`time.sleep(delay_sec)`** 放在**成功拿到响应之后**，避免失败请求也拖慢重试节奏
- **`get_page`** 对 **`RequestException`** 做**最多 3 次**短间隔重试，缓解偶发断连

---

## 2. 异常处理与最佳实践（易错点）

1. **配置与代码搅在一起** → 换站就要动引擎，容易回归出错误
2. **不做安全抽取** → 选择器失效即 `AttributeError` / 空迭代
3. **各站字段不一致** → 下游无法统一分析；应通过 `Content` 对齐
4. **`parse(site, url)` 传错参数** → 第二个参数必须是**当前要抓的页面 URL**，不是把站点列表当 URL 传进去
5. **线上示例选择器长期不变** → 新闻站改版最快，书中 Reuters / NYTimes 等 **class 很可能已变**，以开发者工具实况为准

第 5 条要正面理解：**配置化并不能让你免于改版，只是把「改版」的代价从「改引擎 + 重测所有站」降到「改一个字符串」**。

## 3. 示例代码

主示例：**`chapter-04/crawler_model.py`**

要点：**`Content` / `Website` / `Crawler`** 三类的完整实现、`safe_get`、`display`（方法不能叫 `print`）、**默认延迟**、**`save_to_txt`**，主程序含**离线演示 + example.com 在线演示**两段。

```bash
cd chapter-04
pip install -r requirements.txt
python3 crawler_model.py
```

**运行前建议**：把脚本里的 **`DEFAULT_UA`** / `mailto:you@example.com` 改成你自己的标识与联系方式。

脚本里 `example.com` 那段的 `title_selector` 写的是 **`"h1, title"`**，不是单个 `h1` —— 因为 IANA 早年给的 `example.com` 有 `<h1>Example Domain</h1>`，后来简化成只剩 `<title>`，单写 `h1` 会抽到空串。逗号是 **CSS 选择器组**，按文档顺序取第一个命中项。这正好是第 1.2 节「改版时改配置、不改引擎」的实例：站点变了，只动了一个字符串。

## 4. 学习贴士

- **判断一个爬虫设计好不好，看「加一个站要改几个文件」**。答案应该是 1 个（配置文件），而不是 3 个。
- **`safe_get` 是这套设计的关键零件**。没有它，配置写错就崩；有了它，配置写错只是返回空字符串 —— 前者要紧急修，后者可以慢慢修。
- **`parse_from_soup` 是为了可测试性**。真正的工程化标志不是「能跑」，是「不联网也能测」。

## 练习建议

1. 运行 `crawler_model.py`，确认离线块与 **example.com** 两段都有输出。
2. 新增一个 **`Website`**，自选一篇结构简单的新闻或博客页，用浏览器 F12 校对 `title_selector` / `body_selector`。
3. 为多条 URL 循环调用 `parse`，适当增大 **`delay_sec`**。
4. 只用 **`parse_from_soup`**，用本地保存的 `.html` 做回归测试（完全无需联网）。
